Banko AI Assistant

One CockroachDB cluster behind a bank, its assistant, its coach and the load that tests it
Browser

Pages, no build step

Jinja templates and Alpine.js over the JSON API: dashboard, accounts, transactions, cash flow, budget, recurring, goals, assistant, coach, agents, platform, settings. Answers stream over SSE; live activity over Socket.IO.

↕
The app (banko-ai run)

Assistant

A LangGraph graph: route, then SQL totals, visits, receipts, memory, a tool planner or the next page, then respond and learn. Each thread is checkpointed by CockroachDBSaver.

Services

The ledger moves money in one short transaction per movement; reads, receipts, memories and per-user caches keyed on the user's data version.

Coach

Spending signals by webhook or Kafka; an agent checks budgets and transactions with tools and writes a nudge.

Receipt, fraud and budget agents

OCR and field extraction, a duplicate check by vector, a posting through the ledger, then the checks on the Agents page.

Load simulator

Simulated customers through the same services, each served in their home region; throughput, latency and money integrity on the Platform page.

AI providers

One abstraction, no other code calls a model SDK.

Outside the app

Model endpoints

Cloud providers, or Ollama on the same machine for airgap. Embeddings are always local (all-MiniLM-L6-v2, 384 dims).

Debezium and Kafka

Changes on spending_signals stream to the coach; the companion pipeline lands them in Iceberg on watsonx.data.

Chaos control plane

Takes a region down and brings it back from the Platform page.
